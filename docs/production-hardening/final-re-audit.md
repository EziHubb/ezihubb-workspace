## Remaining architecture risks discovered or made explicit

- The email verification controller takes a raw property rather than validated DTO. Explicit service validation closes missing-token predicate omission; no claim that every raw-body endpoint is now audited.
- E1 refresh rotation now consumes conditionally and creates a successor in the same transaction. CAS/rollback harness passes; real PostgreSQL contention still unverified. Redis MFA challenge claims and attempt budgets added; data loss/eviction, same TOTP across different challenges and setup/session interactions need broader review.
- E2 guest messaging no longer accepts identifier-only authorization: email proof issues a hashed, expiring/revocable cookie capability scoped to anonymous conversations. Account-owned threads require account identity. Service/controller negative tests pass; real DB/SMTP/cookie integration remains pending. Existing permanently accessible attachment URLs and historical mislink cases are not repaired by this boundary.
- Legacy affiliate CAS guards alone do not fix partial payout. New captured-lot allocations now provide exact versioned liability tracking, but legacy readers/actions and notification/consumer routing are not switched. Fake transaction harnesses are not PostgreSQL contention tests.
- Signed tracking events can still arrive late or be replayed. Signature verification is necessary but not sufficient for valid order transitions.
- Existing data and runtime integrations have not been inspected. UNKNOWN must not be interpreted as clean.
